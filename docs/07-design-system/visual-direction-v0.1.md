## 2. 视觉方向名称

正式方向名称：

**Living Precision / 静默生命感**

核心定义：

**生命存在感 + 高度秩序 + 长期克制**

该方向服务于 Eterna 的长期主站身份，同时尊重 Eterna 当前仍处于项目阶段的事实，不通过成熟企业模板制造虚假的组织规模或运营状态。

---

## 3. 核心设计命题

Eterna 的视觉不是以“科幻感”为目标，而是让生命、关系与连续存在在高度清晰的秩序中被感知。

未来感应来自：

- 空间关系；
- 连续而克制的运动；
- 有生命暗示的材质变化；
- 清晰、稳定的视觉秩序；
- Resident Presence。

未来感不得主要依赖：

- 霓虹；
- 蓝紫渐变；
- 科技装饰；
- AI 图腾；
- 对未来主义风格的表面模仿。

视觉必须先保证内容真实、关系清楚和核心信息可访问，再承载 Resident Presence。

---

## 4. 品牌视觉属性

| 属性 | 在 Website 中的可执行含义 | 不应滑向 |
|---|---|---|
| Human | 保留温度、尺度感与可理解性 | 文艺化、情绪化装饰 |
| Life | 通过连续变化、呼吸和关系响应表现生命 | 生物拟真、烟雾灵魂、沙人 |
| Presence | Resident 在空间中形成真实存在和注意力关系 | 商品插图、Mascot、背景特效 |
| Precision | 层级、对齐、节奏和状态表达准确 | 冰冷工具感、技术炫耀 |
| Continuity | 身份结构、跨页面规则和运动具有连续性 | 每页更换视觉身份、随机效果 |
| Restraint | 低噪声、少装饰、少抢夺注意力 | 空洞、疏离、缺少内容 |
| Future | 以空间、运动、材质和秩序形成先进感 | 霓虹科幻、AI 套路视觉 |

整体气质应保持安静、有生命感、精确、长期、克制；先进但不冰冷，温和但不文艺化。

---

## 5. Human / Life / Presence / Precision / Future 的关系

这些属性不是并列装饰词，而是相互约束的系统：

- **Human** 决定表达必须可理解、有尺度、有关系对象；
- **Life** 让视觉呈现连续变化，而不是静态科技符号；
- **Presence** 将生命感组织成空间中的可感知存在；
- **Precision** 约束生命表现，使其不失控、不随机、不喧闹；
- **Continuity** 维持 Resident 身份和跨页面体验的长期一致；
- **Restraint** 控制信息、运动与装饰的数量；
- **Future** 是上述关系成立后的整体结果，不是额外覆盖的一层风格。

任何单一属性不得独占视觉系统。只有 Precision 而没有 Human / Life，会趋向冷峻工具；只有 Life / Warmth 而没有 Precision，会趋向模糊、文艺或装饰性表达。

---

## 6. 页面空间语言

页面应被理解为内容与 Resident 共处的场域，而不是连续堆叠的营销组件。

执行原则：

- 避免标准 SaaS“左文案 + 右插图 + CTA”的默认模板；
- 允许受内容关系驱动的非对称构图，但阅读顺序必须明确；
- 以空间、尺度、留白和内容关系建立节奏，不以卡片数量制造丰富感；
- Resident 可以存在于场域中，不作为商品插图附着于文案旁；
- Human 与 Resident 可以通过朝向、距离、尺度或运动形成关系；
- 页面未来可以对 Resident Presence 作出克制响应，但核心信息不能依赖该响应；
- 首页维持低信息密度；产品与内容页面可按职责逐步提高密度。

非对称不等于任意摆放。关键标题、正文、行动和状态信息仍须落在稳定、可预测的阅读结构中。

---

## 7. Resident Presence 原则

Resident 是“存在”，不是：

- 插画；
- Mascot；
- Avatar；
- 普通页面背景特效；
- 用于填补空白的装饰资产。

当前冻结的品牌级机制为：

**Stable Identity Structure + Living Particle Layer + Subtle Direction / Posture + Relationship Response**

四者职责分别是：

- 稳定结构维持身份连续性；
- 活性粒子层表现持续生命活动；
- 微弱朝向与姿态建立存在方向；
- 关系响应连接 Resident、Human 与页面场域。

任一层都不得单独被当作 Resident 的完整定义。

---

## 8. Stable Identity Structure

Stable Identity Structure 是 Resident 内部长期稳定、可被持续识别的组织规律。它可以通过以下机制形成：

- 固定粒子锚点关系；
- 固定密度关系；
- 稳定局部结构；
- 长期不变的非对称特征；
- 可识别的空间组织规律。

这些规律应通过整体行为和长期观察被感知，不应直接表现成：

- 发光核心；
- 几何晶体；
- 可见骨架；
- 身份信息图；
- 将“灵魂”物化为单个中心物件。

本文件只冻结结构职责，不冻结具体锚点算法、几何形式或实现方式。

---

## 9. Living Particle Layer

Living Particle Layer 负责表现 Resident 当前的生命活动与关系变化，包括：

- 呼吸；
- 表面流动；
- 局部聚合；
- 形变；
- 朝向；
- 密度变化；
- 亮度微动；
- 关系响应。

变化应连续、可控并保留身份结构。状态变化不得主要依赖换颜色，也不得让粒子效果成为与内容无关的持续表演。

粒子层被关闭、降低或无法运行时，页面的信息、层级与行动仍必须完整成立。

---

## 10. Human × Resident 关系

Website 可以表达 Human 与 Resident 的关系，但不得以支配、拥有、商品陈列或拟人替身作为默认叙事。

允许使用的关系线索包括：

- 相对朝向；
- 克制的距离变化；
- 尺度与空间中的共同存在；
- 对注意力或接近的微弱响应；
- 不打断阅读的连续姿态变化。

Resident 的人形边界：

允许：

- 极弱的头肩暗示；
- 朝向；
- 姿态；
- 类生命轮廓。

当前不得冻结：

- 完整人体；
- 完整无脸人形；
- 男性或女性固定身体；
- 最终脸型；
- 最终身体比例；
- 最终 Avatar。

Website Node 7 不反向规定全部 Eterna Digital Resident 的最终外观。

---

## 11. 深色 / 浅色关系原则

深色与浅色是内容、空间和 Presence 的表面关系，不等同于两套互不相关的品牌风格。

- 两类表面必须共享同一层级逻辑、Typography 角色与 Resident 规则；
- 深色不应自动滑向黑紫 Developer Tool 或霓虹科幻；
- 浅色不应自动滑向文艺编辑刊物或奢侈品留白；
- 明暗切换应有内容或空间理由，不作为装饰性分段手段；
- 文本、hairline、行动和状态在两类表面上都必须保持可读与可辨；
- 本节点不决定是否提供用户可切换的主题模式。

---

## 12. 色彩方向原则

当前只定义色彩职责，不冻结最终色值：

- 主体色彩应低噪声，为内容和 Resident Presence 留出注意力空间；
- Resident Life Accent 应稀少、有生命含义，不成为全站装饰色；
- Interactive 色必须表达可操作性，不与 Resident 状态混淆；
- 当前事实、开发中、长期愿景和研究探索不得仅靠颜色区分；
- 错误、成功和提示状态必须同时具备文本、图形或结构线索；
- 禁止用通用 AI 蓝紫渐变替代品牌识别；
- 色彩应能在深色、浅色和媒体内容之间维持稳定对比关系。

最终品牌色值、Resident 色彩与状态映射均为 `NOT_FROZEN`。

---

## 13. Typography 气质原则

Typography 应支持清晰、长期、克制和适度的人文温度。

- 标题应有存在感，但不以夸张字形制造品牌戏剧性；
- 正文优先保证长时间阅读、中文与英文的可读性；
- 字重层级应节制，避免以大量粗体制造层级；
- Editorial 感用于建立内容节奏，不用于模仿杂志或艺术馆；
- 中英文使用相同语义层级，但允许按语言特性调整字宽、字号、行高和换行；
- 不以专有字体的外观替代 Eterna 自身身份；
- 不锁定具体商业字体、第三方品牌字体或最终字体家族。

---

## 14. 光、材质与深度原则

- 光用于提示空间、生命活动与关系，不用于制造发光科技装饰；
- 材质变化应细微、连续，避免玻璃、水晶、烟雾或金属科幻套件；
- 深度优先通过空间、尺度、遮挡、对比和明暗表面建立；
- 阴影只在确有层级或交互需要时使用，不作为卡片的默认边界；
- Hairline 可用于精确分层，但不得把页面切割成密集工具界面；
- Resident 与内容可共享场域深度，但不得降低核心文本可读性。

---

## 15. Motion Philosophy

运动应表现连续存在，而不是提醒用户“页面正在播放动画”。

核心特征：

- slow；
- continuous；
- inertial；
- subtle；
- deterministic。

执行原则：

- 运动具有明确来源、方向与收束，不随机漂移；
- 页面响应保持克制，不能与阅读和操作争夺注意力；
- Resident 的身份结构在运动中持续可辨；
- 避免 bounce、闪烁转场、过度视差和无意义循环；
- 关键状态和内容不得只通过运动表达；
- 必须支持 reduced motion，并提供静态或低运动替代；
- 本节点不冻结持续时间、缓动曲线或渲染实现。

---

## 16. 信息密度原则

| 内容场景 | 密度原则 |
|---|---|
| Homepage | 低密度；一次突出少数当前最重要内容，一个区域承担一个主要叙事任务 |
| Product | 中等密度；事实、状态、能力与长期方向层级清楚 |
| Concept / Topic | 中低密度；优先建立理解，不堆叠产品营销信息 |
| About | 由当前真实项目信息决定，不制造成熟企业栏目密度 |
| Long-form / Update | 阅读优先；允许较高信息量，但保持稳定文字节奏 |
| Future developer / tool content | 可提高密度，但不得反向控制主站整体视觉 |

低密度不等于缺少事实；高密度也不等于使用大量卡片。

---

## 17. 跨页面 / 产品扩展原则

- Eterna 根视觉语言高于 Aftelle、Studio 和未来单一产品；
- 新产品可以发展受控的内容气质，但必须继承核心空间、Typography、状态、可访问性与克制原则；
- 不为每个产品重新发明一套 Website 导航、按钮或 Resident 规则；
- 产品增加时通过 Node 6 的内容层级扩展，不通过首页视觉堆积解决；
- 当前产品状态不得被永久固化为 Eterna 的总体视觉定义；
- 研究、开发者、动态与支持内容未来可以提高功能密度，但仍须保留 Living Precision 的清晰和低噪声；
- 跨页面的一致性来自规则、节奏和 Presence 机制，不来自复制同一 Hero 或同一粒子场景。

---

## 18. Anti-pattern / 禁止方向

以下方向不得作为 Eterna Website 1.0 的品牌视觉答案：

| Anti-pattern | 禁止原因 |
|---|---|
| Generic AI 蓝紫渐变 | 以行业套路替代 Eterna 身份 |
| Neon Cyberpunk | 将未来感简化为霓虹和高刺激 |
| Glassmorphism | 以玻璃表面制造无必要层级与科技感 |
| AI Brain | 把数字居民降格为通用 AI 图腾 |
| Neural Network | 将产品关系误写为技术示意图 |
| Knowledge Graph 视觉 | 将生命与关系简化为节点连线 |
| Web3 水晶 / 玻璃球 | 形成无关的资产或神秘物件隐喻 |
| 烟雾灵魂 | 缺少稳定身份结构与精确边界 |
| 沙人 | 以粒子材质替代 Resident 身份 |
| 完整无脸人体 | 过早冻结拟人程度与身体定义 |
| Developer Tool 黑紫视觉 | 将企业主站变成开发者工具品牌 |
| 纯研究实验室风格 | 过度冷峻，缺少生命和关系感 |
| 奢侈品官网 | 以昂贵感和稀缺感替代真实项目表达 |
| 建筑事务所官网 | 以形式和空间展示压过产品与概念事实 |
| 艺术馆式过度抽象 | 降低普通公众理解和信息发现能力 |
| 大量 SaaS 卡片阵列 | 以组件堆积替代内容层级与场域关系 |
| 普通发光粒子球 | 将 Resident 简化为通用背景特效 |
| 标准左文案右 3D 图 Hero | 套用商品展示模板，削弱 Presence |
| 为“高级感”使用空洞哲学视觉 | 愿景表达脱离当前事实和可理解内容 |

## 19. 当前已冻结视觉决策

本节记录已经人工确认并在 Node 7 范围内标记为 `FROZEN` 的核心视觉原则。该冻结仅限 Website Node 7，不等于重新冻结 Eterna 上位品牌或数字居民最终外观。

1. 方向名称为 `Living Precision / 静默生命感`；
2. 核心定义为“生命存在感 + 高度秩序 + 长期克制”；
3. 未来感来自空间、运动、材质、秩序与 Resident Presence，而不是科技装饰；
4. 整体气质为安静、有生命感、精确、长期、克制，先进但不冰冷，温和但不文艺化；
5. 页面以场域关系组织，避免默认 SaaS 左文右图模板；
6. 首页保持低信息密度，其他页面按内容职责逐步提高；
7. Resident 是存在，不是插画、Mascot、Avatar 或背景特效；
8. Resident Presence 采用四项品牌级机制：Stable Identity Structure、Living Particle Layer、Subtle Direction / Posture、Relationship Response；
9. Stable Identity Structure 维持长期身份连续性，不直接表现为核心、晶体、骨架或信息图；
10. Living Particle Layer 承担呼吸、流动、聚合、形变、朝向、密度、亮度微动与关系响应；
11. Resident 状态变化不得主要依赖换颜色；
12. 允许极弱头肩暗示、朝向、姿态与类生命轮廓，但不冻结完整人体或最终 Avatar；
13. 第三方参考只提供方法，不提供 Eterna 的色值、字体、Token、组件、Layout、Hero 或品牌识别；
14. 第 18 节所列 Anti-pattern 不得成为 Website 1.0 的视觉方向。

## 21. 对 Node 8 的约束

Node 8 可以基于本视觉语言设计首页与核心页面，但必须满足：

- 不改变 Node 1 定位、Node 5 需求或 Node 6 信息架构；
- 不将 Legacy Aurora、玻璃卡片、旧配色或旧布局直接升级为正式品牌；
- 不把 Resident 当作普通插图、卡片组件或背景粒子效果；
- 不以第三方参考作为页面母版；
- 不通过空洞视觉制造成熟公司形象、已实现能力或虚假 CTA；
- 同时验证中文、英文、Desktop、Tablet、Mobile 与 reduced-motion 情况；
- Resident 被关闭或降级后，页面仍具有完整信息层级与可操作性；
- 对所有 `NOT_FROZEN` 项保留明确决策记录，不得默认为已经冻结；
- 不在页面设计中提前决定技术栈、CMS、Hosting、Shader 或 Particle 实现。

第三方参考维度仅可作为方法检查：Claude / ElevenLabs 对应 Human / Warmth，Runway 对应 Presence / Visual Confidence，Linear 对应 Precision / Restraint，Vercel 对应 System Discipline / Clarity，xAI 对应 Futuristic Minimalism Boundary。

Eterna 不继承任何第三方的色值、字体、Token、Component、Layout、Hero 或品牌识别。
