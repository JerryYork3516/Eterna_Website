## 4. 上位文档优先级

以下关系只总结现有文档已经声明的治理和适用范围：

1. `AGENTS.md`、根 INDEX、分类 INDEX 和 CHANGELOG 决定文件是否属于正式知识库、当前状态与替代关系，但不提供产品正文定义。
2. 《Eterna 核心宪章》是最高层使命、价值与不可违反原则；所有产品、协议和下位文件均受其约束。
3. 《数字居民定义》和《Eterna Universe》在宪章之下按领域分工：前者负责 Resident 身份、连续性和数据边界，后者负责领域平台、公共基础设施和生态拓扑。两者互相引用，不能用其中一个越权覆盖另一个的专属范围。
4. 《Studio North Star》是 Studio 产品级最高方向文件，同时受宪章、数字居民定义和 Universe 约束。
5. `README.md` 的仓库指南针只用于确认各仓库职责及 Website 的官方入口角色，不能覆盖上述产品和领域定义。
6. Website 自身文档只能记录公开表达原则和项目决策，不成为 Eterna、数字居民或其他产品定义的事实源。

## 5. 一致性检查

### 5.1 Eterna 总体使命

- 结论：未发现实质冲突。
- 核心宪章把 Eterna 的长期使命建立在普通人能够创建、合法拥有或控制、培养和迁移数字居民，以及人类与数字智能长期共同发展之上。
- Universe 将该使命展开为以数字居民为中心的长期生态，不把任何单一产品设为中心。
- Website 约束：不得把 Eterna 缩减为聊天产品、单个 App、单个模型或单一产品品牌。

### 5.2 Eterna Universe 产品拓扑

- 结论：未发现实质冲突。
- Universe 明确区分中心主体、领域平台、公共基础设施和研究孵化，并说明长期平台清单不等于已立项、已开发或当前功能承诺。
- Website 约束：不得把长期愿景平台写成已经上线的产品，也不得把平台列表当成 Website 1.0 的页面或施工范围。

### 5.3 数字居民定义

- 结论：未发现实质冲突。
- 核心宪章提供最小定义，数字居民定义 v0.6 提供正式领域定义，Universe 与 Studio 使用同一中心主体与连续性边界。
- Website 约束：不得把模型、Prompt、角色卡、一次会话、临时 Agent、工作流、外观或 Artifact 单独称为完整数字居民。

### 5.4 Studio 产品职责

- 结论：未发现实质冲突。
- Universe 与 Studio North Star 都把 Studio 定位为数字居民的创作、配置、验证、构建和发布平台；Studio 不承担正式长期运行，也不拥有长期实例数据或最终身份解释权。
- Website 约束：不得把 Studio 描述为 Aftelle、Runtime、完整数字居民本体或全 Universe 的总控制平台。

### 5.5 Aftelle 已存在的正式定义

- 结论：现有上位正文中的高层定义一致，但缺少独立产品 North Star。
- 核心宪章、Universe、数字居民定义和 Studio North Star 均把 Aftelle 放在人类与 Resident 长期共存、交互、陪伴、承载、恢复、备份入口和个人运行入口的范围内。
- 同一组文件都限制 Aftelle：不取代 Studio 的创作发布职责，不绕过 Runtime Core 执行能力，也不建立与 Resident Instance Data Authority 竞争的长期事实源。
- Website 约束：只能采用上述高层边界，不能猜测 Aftelle 的完整产品定位、价值主张、功能清单或发布承诺。

### 5.6 Runtime、Studio、Aftelle 与基础设施边界

- 结论：未发现实质冲突。
- Studio 负责定义、构建和发布；Aftelle 负责承载、交互、陪伴与恢复入口；Runtime Core 负责执行和调度；Resident Instance Data Authority 负责长期实例数据事实；Eterna Meta 负责身份、来源和治理。
- Website 约束：公开表达必须保留这些边界，不能把客户端体验、执行层、长期数据权威与身份治理合并成一个模糊“AI 平台”。

### 5.7 Website 表达冲突风险

当前没有专门的 Website 上位正文，因此风险主要来自错误外推：

- 把 Website 当作 Eterna Universe 中新的领域平台或公共基础设施；
- 把 Aftelle 或 Studio 当作 Eterna 全部；
- 把 Universe 长期拓扑描述为当前已实现产品矩阵；
- 把当前产品阶段永久固化成 Eterna 的最终定义；
- 把内部批准候选、长期愿景或研究方向写成对外已批准、已发布或已交付能力；
- 让 Website 文案成为反向修改 Eterna 产品边界的事实源。

### 5.8 仓库状态一致性

- 未发现四份产品与领域正文之间的语义冲突。
- 发现 HEAD 路径与当前工作树 INDEX 路径不一致：HEAD 可复现 `.txt`，工作树 INDEX 指向未提交 `.md`。
- 该问题属于来源快照与治理状态不一致，不由 Website 修复；它是本文件保持 `REVIEW_REQUIRED` 的原因之一。
