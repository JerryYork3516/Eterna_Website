## 1. 网站性质

### 上位事实

- `Eterna_Docs/README.md` 将 `Eterna_Website` 的仓库职责定义为 Eterna 官方网站、品牌展示与公开产品入口。
- 《Eterna Universe》说明 Eterna 是围绕数字居民形成的多领域平台与公共基础设施生态，不是单一产品。
- 数字居民是 Eterna Universe 的中心主体，Studio、Aftelle 和 Runtime Core 各有不同职责，任何单一产品都不能代表 Eterna 全部。

### Website 项目决策

Eterna Website 1.0 定位为 Eterna 的长期项目官网、品牌门户与公开产品体系总入口，而不是单一产品 Landing Page。

这一判断是对“官方网站、品牌展示与公开产品入口”以及多产品 Universe 拓扑的 Website 项目级落实，不是对 Eterna 产品体系新增一个领域平台。Website 是公开表达与入口层，不是 Eterna Universe 的中心主体、领域产品或公共基础设施。

Website 的核心展示对象是 Eterna 项目、Digital Resident、当前有真实依据的产品，以及 Eterna 的长期方向与公开愿景。未来如存在真实且获准公开的法定主体、公司名称、Legal / Privacy、团队或其他公司事实，Website 可以条件式承载，但这些内容不得反向成为 Website 的根定位；公司公开身份当前仍属于已登记缺失项 `N1-GAP-04`。

## 2. 网站目标

| 目标 | 来源属性 | 当前定位 |
| --- | --- | --- |
| 建立统一、长期的 Eterna 项目与品牌表达入口 | Website 项目决策，受 README 仓库职责支持 | 让访问者首先理解 Eterna，而不是误把 Eterna 等同于某个 App 或单项能力 |
| 提供 Eterna 产品体系的公开总入口 | Website 项目决策，受 README 与 Universe 支持 | 以可扩展方式说明产品之间的关系；不在节点 1 决定导航、页面或 URL |
| 准确解释数字居民核心概念 | 上位事实的公共表达职责 | 所有定义性内容追溯到《数字居民定义》，避免把模型、Prompt、Agent 或角色卡称为完整 Resident |
| 展示当前有充分证据支持的核心产品与进展 | Website 项目决策 | 只发布有版本化来源的当前事实；上位文档没有正式指定“旗舰产品”，不得擅自使用该称号 |
| 为研究、开发者、新闻与支持等长期内容保留扩展能力 | Website 项目决策 | 只确认长期可扩展性，不在节点 1 创建栏目、页面、导航、CMS 或内容承诺 |
| 维持公开表达的可追溯性 | Website 项目决策，受 Eterna_Docs 权威关系约束 | 区分上位事实、当前已实现能力、长期愿景和 Website 自身决策 |

Website 1.0 的核心结果不是把尽可能多的长期愿景展示为产品，而是建立一个不会随着产品增加、阶段变化或单一产品升级而失效的 Eterna 总体表达框架。

## 3. 目标受众

以下只定义 Website 层级用户群，不形成详细 Persona、旅程、需求优先级或转化设计。

### Website 项目决策

- 希望首次理解 Eterna、Eterna Universe 和数字居民概念的公众与潜在用户；
- 希望了解并进入 Eterna 当前产品的潜在或现有用户；
- 与数字居民创作相关的 Creator、Resident Designer 和 Developer；其中三类 Studio 用户角色来自 Studio North Star，但 Website 如何服务他们仍是项目决策；
- 希望了解 Eterna 研究方向、开放能力或生态合作可能性的开发者、研究者与合作方；
- 需要查找经过审核的官方动态、产品信息或支持入口的访问者。

新闻、支持、合作和研究内容目前不构成已存在能力承诺。详细受众需求留到节点 5。

## 4. 产品关系表达原则

| 对象 | Website 必须表达的关系 | Website 不得表达为 |
| --- | --- | --- |
| Eterna | 最高层使命、原则与整个产品生态所从属的总体体系 | Aftelle、Studio、单个模型、单个 App 或 Website 本身 |
| Eterna Universe | 以数字居民为中心的长期产品拓扑和生态边界 | 已全部上线的产品矩阵、当前施工清单或单一产品 |
| 数字居民 | 跨平台保持身份与连续性的中心主体 | Prompt、聊天角色、模型、临时 Agent、工作流、外观、Artifact 或一次会话 |
| Studio | Resident 蓝图、模板、能力和相关资产的创作、配置、验证、构建与发布平台 | 居民本体、正式长期运行环境、长期实例数据权威源或 Aftelle |
| Aftelle | 人类与 Resident 长期共存、交互、陪伴、承载、恢复与个人运行入口 | Studio、Runtime Core、完整数据权威源，或未经 North Star 支持的完整产品承诺 |
| Runtime Core | Resident 逻辑、权限、任务、状态更新和能力调用的执行与调度核心 | 用户品牌门户、长期实例数据事实源或 Resident 本体 |
| Resident Instance Data Authority | 长期记忆、关系、成长和持续状态的受治理事实职责 | Studio、Aftelle 或某个不可替代的单一供应商 |
| Eterna Meta | Resident 身份、来源、谱系、授权与治理基础设施 | 日常运行产品、社交平台或 Website 身份系统 |
| Website | Eterna 的公开表达、品牌展示与产品入口 | 新的 Universe 领域平台、产品定义权威源或 Runtime |

### 表达时序原则

- 先说明 Eterna 与数字居民，再说明产品如何分别服务 Resident；
- 清楚区分“当前已验证”“当前推进”“长期拓扑”“研究候选”；
- 不把 Universe 的长期平台名称自动转化为 Website 页面、导航或发布承诺；
- 产品增加时保持 Eterna 与数字居民的上位结构稳定，不通过重写品牌根定义解决产品扩展。

## 5. Website 职责

### Website 项目决策

Eterna Website 负责：

- 对外建立一致、可持续的 Eterna 总体认识；
- 承载经过审核的品牌表达，并在品牌规范补齐后遵守其约束；
- 解释 Eterna、Eterna Universe、数字居民与各产品之间的层级和职责；
- 为当前有证据支持的产品、能力和官方入口提供统一发现路径；
- 对公开内容标明或维护可追溯来源，避免长期愿景与当前能力混写；
- 为未来增加产品、研究、开发者、新闻和支持内容保留信息层面的扩展能力；
- 在上位定义或产品事实变化时触发内容复核，而不是静默保留过时描述。

这些职责是 Website 项目治理结论，不代表上述内容栏目、服务或系统已经存在。

---

## 6. Website 非职责

Website 不承担以下职责：

- Website 不是 Aftelle 本身，不承载或运行 Resident 的陪伴与交互体验；
- Website 不是 Studio 本身，不负责 ResidentBlueprint 的编辑、构建或发布；
- Website 不承担 Runtime Core 的执行与调度；
- Website 不承担 Resident Instance Data Authority、Eterna Meta 或其他公共基础设施职责；
- Website 不重新定义数字居民，也不把传播性简化变成新的正式定义；
- Website 不成为 Eterna 产品定义的事实源；
- Website 不修改、合并或扩张 Studio、Aftelle、Runtime 或其他 Universe 平台边界；
- Website 不把长期愿景、研究方向、候选产品或内部批准候选文件包装成当前已实现能力；
- Website 不用营销需要覆盖来源、授权、安全、连续性和用户权利约束；
- Website 不在节点 1 决定产品开发路线或 Website 技术实现。

## 7. Website 1.0 当前范围

### Website 项目决策

节点 1 在 `REVIEW_REQUIRED` 阶段用于记录并拟冻结以下规划边界；经本次自检未发现实质冲突，现将这些边界标记为 `FROZEN`：

- Website 的长期性质、总体目标和非职责；
- Website 层级的受众类别；
- Eterna、Universe、数字居民及核心产品的关系表达原则；
- 公开内容的事实来源、当前与未来状态区分及长期可扩展原则；
- 当前无法由 Eterna_Docs 解决的已登记缺失项和待人工决策项。

节点 1 不决定：

- 页面完整清单；
- 导航结构；
- URL 结构；
- 视觉设计或品牌资产；
- 技术栈与技术架构；
- CMS；
- SEO 实现；
- 页面组件；
- 开发计划或代码实现。

以上内容必须进入对应后续节点后再审议。本文件不能被解释为 Website 1.0 已开始开发。

## 8. 长期原则

### Website 项目决策

1. Website 采用长期项目官网结构，新增产品或公共内容时不要求重建 Eterna 品牌根架构。
2. Eterna 与数字居民保持为稳定上位叙事；单一产品、单一阶段或单一技术不得取代总体定义。
3. 所有定义性表达应能追溯到 Eterna_Docs 的明确文件、版本和 commit；产品现状应追溯到对应产品的可验证来源。
4. Website 不把当前产品状态永久固化成 Eterna 的最终定义。
5. Website 不把未来愿景、研究方向、规划平台或候选文档伪装成当前已经实现的能力。
6. 对外简化不得改变 Resident、Studio、Aftelle、Runtime、长期数据权威和身份治理之间的边界。
7. 上位文档升级、替代或改变审核状态时，Website 相关表达必须进入复核，而不是静默沿用。
8. 缺少正式来源的公司、品牌、产品或能力信息应保持为对应的已登记缺失项状态，不以聊天记录、常识或营销惯例补齐。
9. Website 是公开表达与入口，不取得产品定义权、居民数据权或运行控制权。
10. 长期可扩展性只在定位层冻结；具体信息架构、页面和技术承载方式留给后续节点。
