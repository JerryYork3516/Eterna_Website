## 1. 研究目的与范围

本节点研究四个具有复杂品牌、产品或内容体系的网站：

- Apple；
- Google；
- Microsoft；
- OpenAI。

研究只回答：这些网站如何在首页、顶层分类、内容层级和 Footer 之间分配信息职责，以及哪些方法可供 Eterna Website 1.0 后续规划参考。

本节点不回答：

- Eterna 应设置哪些页面、导航或 URL；
- Eterna 应采用什么视觉、组件或动效；
- Eterna 应如何选择技术栈；
- 哪个参考网站更好，或 Eterna 应模仿哪个网站。

### 1.1 轻量核对来源

| 对象 | 官方来源 | 本次核对重点 |
| --- | --- | --- |
| Apple | [apple.com](https://www.apple.com/) | 顶层产品入口、Support、首页主题区块与 CTA |
| Google | [about.google](https://about.google/) | About 顶层分类、内容下钻与 Footer 资源组织 |
| Microsoft | [microsoft.com](https://www.microsoft.com/) | Personal / Business 情境分流、产品层级与 Footer |
| OpenAI | [openai.com](https://openai.com/) | 稳定顶层类别、首页时效内容类型与 Footer 体系 |

网站内容会随时间变化。本文件冻结的是本次观察后形成的方法性启示，不把参考网站当前栏目视为 Eterna 的永久事实或目标结构。

## 2. Apple：聚焦与克制

### 2.1 核心观察

- 顶层导航以核心产品类别和 Support 为主；
- 首页主要区块通常围绕一个产品、事件或行动展开；
- 标题简短，首页解释克制，详细内容进入对应产品层级；
- 首页承担当前重点展示，不承担企业全部信息目录的职责。

### 2.2 Eterna 可吸收的方法

- 首页一次只突出少数当前最重要内容；
- 一个内容区块只承担一个主要叙事任务；
- 产品深度内容进入对应产品层级，不在首页完成全部解释；
- 首页聚焦不等于减少 Eterna 的长期体系，而是控制首页的叙事负担。

### 2.3 不得直接继承

- Apple 的购物导向；
- 大量 Buy / Shop CTA；
- 成熟硬件公司的产品展示密度；
- Apple 的具体版式、组件、品牌语言或视觉风格。

---

## 3. Google：少而稳定的顶层分类

### 3.1 核心观察

About Google 当前顶层核心分类主要为：

- About；
- Products；
- Company Info；
- News。

研究、开发者、品牌资源、公益、支持等更复杂内容在下一层和 Footer 继续展开。顶层分类保持精简，不要求每一种内容都成为主导航入口。

### 3.2 Eterna 可吸收的方法

- 顶层信息类别保持少而稳定；
- 产品、企业与动态内容保持职责分离；
- Footer 可以承载大量低频但必要的企业入口；
- 网站未来扩张不意味着主导航持续增加；
- 复杂内容可以通过层级和辅助入口展开，而不是全部堆叠在首页。

### 3.3 不得直接继承

- Google 当前庞大的跨域网站体系；
- 在 Eterna 当前规模下制造不必要的网站碎片；
- Google 的具体栏目名称、页面关系或品牌表达。

---

## 4. Microsoft：通过受众、场景和业务层级管理规模

### 4.1 核心观察

- 首页明确区分 Personal / Business 等使用情境；
- 产品体系规模庞大，但不同入口承担不同职责；
- 产品、开发者、企业、支持和法律内容通过层级与 Footer 继续展开；
- 首页不要求同时解释全部产品和全部受众。

### 4.2 Eterna 可吸收的方法

- 未来出现明显不同用户群时，可以考虑受众级分流；
- 产品增加后依靠分类和层级扩张，不把所有产品平铺在首页；
- 企业、开发者与支持体系应允许独立成长；
- 不同入口的职责应明确，避免同一入口同时承担产品发现、支持和企业治理。

“可以考虑受众级分流”是长期参考原则，不是 Node 4 对 Website 1.0 导航或页面作出的决定。

### 4.3 不得直接继承

- Microsoft 当前极高的信息密度；
- 复杂企业销售结构；
- 当前 Eterna 尚不需要的多层业务入口；
- Microsoft 的具体导航、Footer 分组或页面结构。

---

## 5. OpenAI：稳定结构与快速变化内容并存

### 5.1 核心观察

OpenAI 当前顶层长期类别包括：

- Research；
- Products；
- Business；
- Developers；
- Company。

首页同时持续承载产品发布、Recent News、Stories、Latest Research、Business 内容和产品入口。长期类别相对稳定，首页内容则可以随发布与重点变化。

### 5.2 Eterna 可吸收的方法

- 顶层结构保持长期稳定；
- 首页内容可以随当前重点持续更新；
- 产品、研究、公司动态等内容应具有明确类型；
- 长期稳定内容与时间敏感内容分离；
- Footer 可以形成相对完整的网站体系地图；
- 当前重点变化不应迫使网站根结构反复重建。

### 5.3 不得直接继承

- OpenAI 当前较高的首页内容流密度；
- ChatGPT 式产品直接嵌入首页的交互方式；
- OpenAI 的具体栏目、内容卡片、品牌语言或视觉表现。

---

## 6. 四家案例的共同方法

四家网站的规模、业务和内容不同，但可观察到以下共同方法：

1. 顶层入口数量受到控制，复杂度通过下层内容与 Footer 分担；
2. 首页重点与完整网站体系不是同一件事；
3. 产品、企业、支持、研究、开发者或动态内容具有不同职责；
4. 产品与内容增加时，优先扩展分类和层级，而不是无限增加首页区块或主导航项；
5. 稳定结构可以承载持续变化的当前重点；
6. 大型网站的方法可借鉴，但其规模、销售结构和信息密度不能直接移植到 Eterna。

这些是信息组织方法，不是 Website 1.0 页面方案。

## 7. Eterna Website 1.0 综合参考原则

1. 首页聚焦，不承担解释完整 Eterna Universe 的任务。
2. Eterna 总品牌高于 Aftelle、Studio 或任何未来单一产品。
3. 顶层信息分类应少、稳定、长期可扩展。
4. 产品数量增加时通过信息架构扩张，不通过首页堆积解决。
5. 企业内容、产品内容、研究内容、开发者内容、动态内容和支持内容应保持职责边界。
6. 当前产品事实、正在推进状态、长期愿景和研究探索必须明确区分。
7. 首页应允许当前重点随时间变化，而网站根架构保持稳定。
8. Footer 可以承担大量低频、治理、企业和辅助入口。
9. 任何参考网站都只吸收方法，不复制页面、组件、品牌语言或视觉风格。
10. Website 1.0 最终视觉品质不由 Node 4 决定。

以上原则用于约束后续规划判断，不在 Node 4 中直接生成页面、导航、内容清单或视觉方案。

## 8. 对后续 Node 5–8 的参考边界

- Node 5 可使用本文件判断不同内容职责是否需要被定义，但不能把参考网站栏目直接转化为 Eterna 需求；
- Node 6 可使用“少而稳定、通过层级扩张、Footer 分担低频入口”等原则评估信息架构，但必须从 Eterna 自身需求出发；
- Node 7 可确认视觉系统应服务稳定品牌与多类内容，但不得复制四家网站的品牌语言或视觉；
- Node 8 可在已经冻结的需求、信息架构和设计系统下处理产品设计，本文件不提供页面版式或组件方案。

本文件不提前替代 Node 5–8 的研究、决策与人工审核。
